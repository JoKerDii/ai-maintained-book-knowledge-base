# Reshuffle — Decision Cheatsheet

## The one reframe
When you catch yourself asking **"How smart is the AI?"** or **"What can we automate?"**, stop. Ask **"What does this system look like once it adopts the machine's logic?"** — because AI's economic impact comes from restructuring the system around a task, not from performing the task.

## Diagnostic order (never invert)
1. Has the **playing field** (system/ecosystem) changed?
2. Has the **basis of value creation** moved?
3. Does the **business model** still hold?
4. What **capabilities** does the new game need?
5. Which **roles and workflows** still matter?
6. *Only now* — where does AI apply?
> Starting at step 6 is the framing error. It produces motion, not direction.

## Constraint router — where does my value come from?
| Your value rests on | AI's effect | Do this |
|---|---|---|
| **Scarcity** (rare knowledge, gated access) | Collapses fastest — expertise commoditizes | Exit; rebundle around risk or coordination |
| **Risk** (errors are costly, someone must be accountable) | Grows — probabilistic outputs create accountability gaps | Own judgment, liability, and trust |
| **Coordination** (many misaligned moving parts) | Grows most — AI extends coordination into new domains | Own representation, decision, and execution |

## Is this task safe? — displacement test
- Did it get **cheaper**? → economic displacement.
- Did it stop **mattering in the workflow**? → contextual displacement.
- Either one devalues the job. A task can feel meaningful (**intrinsic value**), still be done, and command nothing.
- **Typist effect tell**: the task still exists but no one needs a person whose job *is* that task.

## Reskilling: when it actually works
- **Works** when the system still needs a human to execute that work.
- **Fails** when the system has removed the need. Then only **rebundling around the new constraint** works.
- Default: stop asking "what skill next?" and ask "where has friction moved?"

## Tool vs. Engine
| | AI as a **Tool** | AI as an **Engine** |
|---|---|---|
| Role | Optimizes tasks in the current model | Determines core system performance |
| Effect | Competes better at the old game | Changes the rules of competition |
| Replaceable? | Yes | Not without re-architecting |
> If your AI could be swapped out without redesigning the business, it's a tool — expect no durable advantage.

## Am I becoming a wrapper? — the integration trap, 3 stages
1. Tools **commoditize execution**.
2. Tools **absorb expertise**.
3. You **reorganize around the engine** → performance-based lock-in.
**Tells**: you dropped internal processes because they "just add complexity"; your performance gains now arrive from the vendor's release notes; customers can't name what's yours.
**Move**: keep a layer the engine can't see — proprietary field data, risk absorption, decision rights, integrated delivery.

## How far to climb the solutioning stack
| Model | Paid for | Requires |
|---|---|---|
| Work-as-a-service | Operational delivery (hours, cycles) | Tool performance ownership |
| Results-as-a-service | Measurable results to spec | Domain depth + deeper integration |
| Outcomes-as-a-service | Customer-specific strategic outcomes | End-to-end control, liability, monitoring |
**Rule**: climb only as far as you can absorb the risk. Liability without visibility, integration, and execution control is a loss engine.

## Consensus or interpretation?
- Participants **can** be made to adopt shared standards → **coordination with consensus** (CCC model): auditable, enforceable, slow to spread.
- Participants **won't ever** agree on formats → **coordination without consensus** (Tractable model): AI interprets each actor's native inputs; standards become implicit. This is the domain AI newly opens.
- **Tell that you need the latter**: repeated failed attempts to get everyone onto one platform.

## Control point checklist (all three, or you don't have one)
- **Unified representation** — shared source of truth everyone acts on
- **Unified decision** — you resolve the decision they'd otherwise negotiate
- **Unified execution** — workflows integrated so the decision actually happens
> UI simplification alone never earns the right to coordinate. Power comes from **dependence, not dominance**.

## Where the control point sits
- Customers stuck on a hard choice → **demand-side control point** (own the decision moment).
- Partners can't align on delivery → **supply-side control point** (own the coordination anchor).

## Four strategic postures — pick one out loud
| Posture | Move | Advantage |
|---|---|---|
| Reactive optimizer | Speed up today's tasks | None that compounds |
| Anticipator ("Gretzky") | Spot value migration early | Incremental; still the old game |
| Logic shifter ("Curry") | Change where/how decisions are made | Structural, within the industry |
| Field reshaper ("Tiger") | Restructure the ecosystem | Most durable; you set others' rules |
**Rule**: the deeper the reimagining of coordination, the greater the power shift and the more enduring the advantage.

## Three traps when the ground keeps shifting
- **Chase transient advantage** → wins evaporate, never compound (Chegg).
- **Build executional agility** → faster at solving the wrong problem (Yahoo).
- **Perpetual experimentation** → motion without commitment.
> All three optimize *within* the old system and tether you to it.

## Smells
- "We need an AI strategy." → You need a strategy for the conditions AI creates.
- AI pilots proliferating with no system thesis → execution bias.
- Outputs that look impressive but lack rigor → vibe coding.
- Task-level speedups + rising cross-team friction → **coordination paradox**; you fragmented the org.
- "Humans stay in the loop, so we're fine." → **human-in-the-loop illusion**; check who actually decides.
- Everyone's output suddenly looks alike → **collapse of differentiation**; the skill premium is gone.
